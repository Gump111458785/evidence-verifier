**一个后端开发案例通过，不是准确率评测。** 使用DeepSeek真实模型及搜索API，保留[此前失败](browser-validation-2026-11-02.md)，没有修改历史标签、丢弃无效事实或执行训练。当前改动在main；旧v0.3.2下载包保持原样。

## 输入与运行条件

问题为`Who designed the Analytical Engine?`，候选`Charles Babbage`；人工声明目标`Analytical Engine → designed_by → Charles Babbage`。受控不充分种子为`The Analytical Engine was never completed.`，初始核验为missing。

四个角色配置deepseek-flash、JSON object、reasoning_effort=none，temperature=0、不发送seed；这不保证供应商完全确定性。本轮使用纯API启动器，不加载本地权重。输入、期望、提示词所在源码哈希在每次实测前冻结；修复后的复测属于开发，不能作为留出验证。[脱敏冻结与结果摘要](data/web-grounding-2026-11-02.json)。

## 修复及其边界

1. **原文分句**：修复`Difference Engine No. 2`被旧分句器从`No.`处截开的情况。只合并同一行相邻片段，保留原字符与偏移；历史内核与归档预测未改。
2. **先检查整批定位**：全部假设通过实体与计算前提定位后才调用语义核验；一条仍无效则整批invalid_output，不把失败算作missing，不丢弃坏事实。
3. **有界邻句补齐**：针对原引用内未出现的实体，在同文档前后各2句定位并加入全部中间句；额外字符超过600则拒绝扩展，不截断。只补引用，不改变实体或关系。新增上下文仍须接受独立支持性核验。
4. **一次可选模型修正**：显式设置`grounding_repair_attempts=1`才启用上述补齐和至多一次定位修正。模型不看问题、候选或目标，不能增删事实、跨原文档借实体，不能改变关系、极性、时间限定或端点类型。失败继续保留；网络错误无自动重试。
5. **引用内独立核验**：核验器只收到每条事实实际引用的句子，不再收到全部正文，避免其他未引用段落替它证明关系。结果保留原假设、补齐记录、逐事实语义结果及原文位置回放。

## 实测结果

| 本轮开发步骤 | 结果 |
|---|---|
| 仅加入一次模型定位修正 | 仍invalid_output；模型没有修复代词所缺的主体，未进入语义核验，保留失败 |

| 自动工具流程 | 真实search一次、open三次，共4次共享工具调用；open读取搜索API返回的正文，不另行抓取网址 |

| 补充提示词 | 已生成，automatically_sent=false；没有自动发送给ChatGPT或其他AI |

复测复用了已完成的初始missing核验，重新执行网页补搜与重核验；不是两次独立完整任务。两次新尝试合计8次模型调用、2次搜索。此前用量另外保留。

成功轮4条抽取假设全部进入独立支持性核验：

| 假设 | 独立判定与开发复查 |
|---|---|
| Analytical Engine由Charles Babbage设计 | entailed；引用直接写明`Charles Babbage commenced work on the design of the Analytical Engine in 1834`，对象是整机，而非只证明一个试验部件 |
| Difference Engine No. 2由Babbage设计 | entailed；同文档邻句补齐代词主体后再核验 |
| Babbage在Cambridge受教育 | entailed；原文明确went to study at Cambridge |
| Babbage在Cambridge受雇 | missing；学习、毕业和学会会员资格不能证明受雇 |

另用**同批已核验事实**检查错误设计者Ada Lovelace、主客体互换、Royal Society会员资格推雇佣三个目标，均为missing。这是3个匹配负例，不是3次独立端到端任务，也不是三类错误率的统计。上述语义复查由开发助手完成，不冒充独立人工双标。
