# Trisight 参赛站接入

参赛页面使用 [现有 Qoder Sites 地址](https://trisight-o4mn67jtib8.qoder.zone/)。审阅 API 使用 [现有 EdgeOne 项目](https://console.tencentcloud.com/edgeone/pages/project/makers-z7l7raqtginj)，沿用 DeepSeek 与 Upstash。浏览案例无需调用模型。开始审阅时，页面自动获取有效期 24 小时的访客会话。该会话只能访问自己的参赛审阅记录。

## 在原 Qoder 站点发布

1. 用创建站点的队友账号打开 Qoder CN，进入「站点 → 我的站点」，找到参赛站，通过「更多 → 定位到会话」返回原任务。也可以由具有该站编辑权限的成员操作。
2. 把 [参赛接入脚本](../deploy/qoder/qoder-demo.js) 附到会话，发送下方修改要求。
3. 检查页面预览，随后在站点面板右上角点「发布」。浏览器预览域名可能和正式域名不同，实时接口联调以正式地址为准。
4. 在「分享 → 更改访问范围」确认设置为「任何人都可访问」，用无痕窗口直接打开原参赛地址。[Qoder 官方文档](https://docs.qoder.cn/qoder/sites)

```text
在现有 Trisight 参赛站更新，不新建站点。保留首页、审阅、案例库、问答历史、
现有设计和 Qoder 平台标识。用附件替换站点发布目录的 /qoder-demo.js，确保
它在 trisight.js 前加载，并删除旧脚本中返回静态 501 的拦截及“静态演示”提示。

页面面向无需登录的访客：顶部改为“访客体验”，隐藏登录、退出登录、个人资料、
账号管理和研究授权入口。首页及案例库的审阅入口均留在当前 qoder.zone 站点，
点击后打开 /assist.html。/history.html 仅展示当前浏览器标签页会话的记录。

实时任务使用附件提供的跨域接入：自动获取访客会话，向 EdgeOne 提交 /api/assist，
按返回的 advance_path 逐步推进。显示实际进度和后端返回的结果。网络、配额及服务
失败时显示明确提示和案例库入口。预设案例仍标明来源，实时审阅失败时不要显示预设
结果作为实时结论。若站点配置限制 connect-src，允许 https://evidence-verifier.edgeone.dev。

该站点只需要公开 API 地址，严禁加入 DeepSeek Key、Redis Key、访问码或任何团队账号密码。
在审阅按钮旁简要提示输入会提交到审阅服务，建议使用公开内容。完成后保留原地址发布。
```

## 发布后检查

- 无痕打开首页和审阅页面，确认两处均不跳转到登录页或 EdgeOne 网页。
- 在审阅页提交短的公开问答，确认呈现的是实时审阅。应能看到分步进度、实际结果，并在同一标签页刷新后看到自己的历史记录。
- 另开独立无痕会话，确认看不到前一访客的历史。检查未配置、服务不可用或额度用完时的提示。
- 用评委所在地网络验收。EdgeOne 默认域名在中国大陆可能要求临时签名，Qoder 地址可打开并不代表其外部 API 也可达。需要稳定大陆访问时，使用已控制的自定义 HTTPS API 域名，并同步更新脚本中的 `backend`。[EdgeOne 域名说明](https://pages.edgeone.ai/document/domain-overview)

每个访客会话最多提交两次，累计最多 5 次模型或检索请求。全站访客创建上限为 40 条任务，付费请求沿用 EdgeOne 现有 10 元共享总账本，每次请求预留 0.25 元。模型和搜索请求按后台实际调用计数，案例库和读取记录不扣费。
